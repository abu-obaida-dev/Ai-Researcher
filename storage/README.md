# Structure of uploaded project files

This directory is used for project-local file storage (outside the database).
Metadata for every stored file is kept in PostgreSQL tables, and the file bytes live here.

## Top-level directories

- `library/` — central research library for reusable references and papers
  - `library/references/` — reference files stored once in the shared library
  - `library/research-papers/` — research papers and academic documents
- `users/` — user-specific content
  - `users/notes/` — personal notes generated by users
  - `users/files/` — uploaded research files belonging to individual users
  - `users/uploads/` — temporary or general uploads before processing

## Important rule

- The shared library stores the original source file once.
- A user reference should only store a metadata reference or a link to that library item.
- User-specific folders should not duplicate the same library file unless there is a real need.

## Recommended naming pattern

- `library/references/{referenceId}-{slug}.pdf`
- `library/research-papers/{paperId}-{slug}.pdf`
- `users/{userId}/files/{fileId}-{slug}.pdf`
- `users/{userId}/notes/{noteId}-{slug}.md`
- `users/{userId}/uploads/{timestamp}-{originalName}`

## Example flow

1. A research paper is uploaded to the shared library.
2. Firestore stores metadata about that paper.
3. When a user selects or bookmarks it, we store only a pointer/reference in the user profile.
4. User notes remain in their own notes folder and do not duplicate research library files.
